## 7.1 Ресурсы и двойная мана

**Ресурсы персонажа:**

| Ресурс | Макс. (база) | Восстановление |
|---|---|---|
| Здоровье (HP) | по классу/уровню | по правилам боя/расходникам |
| Боевая мана (пул A) | 200 | восстанавливается в бою (и вне боя) |
| Резервная мана (пул B) | 200 | НЕ восстанавливается в бою; вне боя — см. раздел 11 |

(Названия «боевая/резервная мана» — рабочие.)

**Правило списания обычной «Маны» (Mana):** сначала тратится пул A; когда A исчерпан, остаток списывается из пула B. Пример: стоимость 60, в A осталось 40 → A=0, B −20.

**Типы стоимости навыка (`CostEntry`):**

```
CostEntry {
  Resource: Mana | CombatMana | ReserveMana | Health
  Amount:   число
  Mode:     Flat | PercentOfMax
}
```

- `Mana` — «умное» списание: A, затем B.
- `CombatMana` — только из пула A. `ReserveMana` — только из пула B.
- `Health` — из HP.
- Навык может иметь несколько `CostEntry` одновременно (например: 40 CombatMana + 30 ReserveMana + 10% HP).

**Правила проверки (на сервере, атомарно):**
1. Проверить, что ВСЕ части стоимости оплачиваемы, иначе навык не применяется и ничего не списывается.
2. Списать все части в одной операции.
3. Стоимость в HP не может убить применяющего: минимум остаётся 1 HP (ДЕФОЛТ).
4. Для навыков с временем каста: проверка при начале и при завершении, списание при завершении (ДЕФОЛТ).

**Боевое состояние:** вход в бой при нанесении/получении урона или применении боевого навыка; выход — через N секунд без боевых действий (ДЕФОЛТ: 6 с). От него зависит регенерация и некоторые эффекты.

**Регенерация:** в бою пул A восстанавливается тиками (значение в данных класса) и за попадания (ДЕФОЛТ: небольшой прирост за успешный автоудар). Пул B в бою не восстанавливается.

**Модификаторы:** предметы, таланты и баффы могут менять максимум пулов и скорость регенерации. Базовые 200/200 — стартовые значения (ДЕФОЛТ: растут от уровня/экипировки, стартуют с 200).

## 7.2 Навыки и их варианты (Shift / Ctrl)

**Модификаторы ввода:**

| Зажато | Вариант | Идея |
|---|---|---|
| ничего | Default (обычный) | базовая версия |
| Shift | Empowered (усиленный) | дороже, сильнее, часто с доп. эффектом |
| Ctrl | Weakened (ослабленный) | дешевле, слабее, короче КД |

Если зажаты оба — применяется обычный вариант (ДЕФОЛТ).

**Модель данных:**

```
SkillDefinition {
  Id, NameKey, DescriptionKey, Icon, TargetType, Range
  Default:   SkillVariant   // обязателен
  Empowered: SkillVariant?  // если null — вариант недоступен, применяется Default
  Weakened:  SkillVariant?  // если null — вариант недоступен, применяется Default
}

SkillVariant {
  Costs: CostEntry[]
  CastTime, Cooldown
  Effects: EffectDefinition[]   // урон, лечение, баффы, контроль, и т.д.
  Flags: (мгновенный, канальный, прерываемый, ...)
}
```

**Команда клиента → серверу:** `CmdUseSkill { skillId, targetId, modifier: None|Shift|Ctrl, clientSeq }`. Сервер сам решает, какой вариант применить, и проверяет, что он существует и разблокирован.

**Правила:**
- Один навык — один общий таймер перезарядки. Длительность КД берётся из применённого варианта.
- Есть глобальный КД (GCD) для базовых навыков (ДЕФОЛТ: 0,8 с; значение в данных).
- Баланс вариантов: ослабленный не должен строго превосходить обычный. Стартовые гипотезы для настройки: Weakened — стоимость ≈ ×0,5, эффект ≈ ×0,6, КД короче; Empowered — стоимость ≈ ×1,7, эффект ≈ ×1,6 плюс дополнительный эффект, КД длиннее. Это гипотезы, их надо проверять таблицей баланса и симулятором боя.
- UI панели навыков: при зажатом Shift/Ctrl иконки и подсказки показывают стоимость и эффект соответствующего варианта.
- Модификаторы переназначаемы. Спринт не вешать на Shift (конфликт): ДЕФОЛТ — спринт/бег на отдельной клавише или авто-бег.
- Заметка по тестированию: в редакторе Unity Ctrl+цифры по умолчанию открывают окна редактора, поэтому ввод Ctrl-вариантов проверять в билде либо временно переназначить сочетания.

## 7.3 Классы персонажей

**Модель данных:**

```
ClassDefinition {
  Id, NameKey, Role: Tank | Healer | Damage | Support
  BaseStats, StatGrowthPerLevel
  ResourceProfile: макс. HP, множители пулов A/B, скорости регенерации
  Skills: (SkillDefinition, LevelUnlock)[]
  TalentTrees: до 3 веток (позже)
  EquipmentRules: допустимые типы брони и оружия
}
```

**Черновик стартовых классов (НЕ утверждено, нужно моё решение):**

| Класс | Роль | Идея по ресурсам |
|---|---|---|
| Воин | ближний бой, танк/урон | основной упор на боевую ману и HP-навыки (жертвует здоровьем ради силы) |
| Маг | дальний урон | сильные навыки, тянущие из обоих пулов; резерв — «запас на сложный момент» |
| (рекомендация) Целитель/поддержка | лечение | нужен до подземелья на 50 игроков: без лечения рейд невозможен |

Каждый класс должен ощущаться по-разному именно через двойную ману и варианты Shift/Ctrl, а не только через набор навыков.

## 7.12 Боевые характеристики, баффы/дебаффы, зелья

**Ключевые боевые характеристики:**
- **Оборона** (`Defense`) — ключевой параметр, выражается как **процент уменьшения получаемого урона**: `полученный урон = урон × (1 − Оборона%)`. Верхний предел обороны задаётся данными (ДЕФОЛТ: 75%), чтобы не было неуязвимости.
- **Критический шанс** (`CritChance`, %) и **размер крита** (`CritSize`: множитель урона при крите, ДЕФОЛТ базовый ×1,5). Бросок крита делает только сервер. Крит применяется к урону и лечению (ДЕФОЛТ). Верхний предел шанса задаётся данными.
- Порядок расчёта урона (ДЕФОЛТ): базовый урон навыка × (1 + бонусы урона) → бросок крита (шанс, размер) → снижение обороной цели → округление, минимум 1.
- Варианты навыков (7.2) могут менять крит. шанс, размер крита и эффекты, у каждого варианта это поля данных.
- Хранение: доли в данных, отображение в процентах в интерфейсе.

**Модель характеристик:** итоговое значение = база + класс + уровень + источники-модификаторы (предметы, слоты, баффы, дебаффы, зелья, постоянные бонусы).

```
StatModifier { Stat, Operation: Add | PercentAdd | Multiply, Value, SourceId }
Порядок: база → Add → PercentAdd (сумма) → Multiply → капы
```

`SourceId` позволяет снять все модификаторы одного источника (предмет, бафф, зелье) и добавить новые типы источников без переписывания системы.

**Баффы и дебаффы (статус-эффекты):**

```
StatusEffectDefinition {
  Id, NameKey, Icon
  Kind: Buff | Debuff
  Category: Stat | DoT/HoT | Control | Shield | Special
  Duration (в т.ч. до снятия), TickInterval
  Stacking: Refresh | AddStacks | ReplaceStronger,  MaxStacks
  Dispellable, DispelType, ImmunityTags
  Modifiers: StatModifier[]
  Triggers / HandlerKey (уникальные эффекты, раздел 7.10)
}
```

- Источники: навыки, предметы, ауры, зелья, события, бонус опыта (например, «x2 опыта»).
- Сервер хранит статус со временем окончания и источником; клиент только отображает. Статусы сохраняются при выходе из игры; идёт ли время, пока игрок не в сети, определяется данными (ДЕФОЛТ: время идёт только онлайн).
- UI: иконки с таймерами у рамок игрока, цели и группы; разделение баффов и дебаффов по цвету рамки; подсказка с описанием; лимит отображаемых иконок.
- Сеть: статус передаётся компактно (ID, стаки, время окончания) и только игрокам из зоны интереса.

**Зелья:**
- Зелье — расходник (`Category = Расходник`) с эффектом. Эффекты задаются данными и используют те же статус-эффекты и модификаторы, отдельного кода под каждое зелье нет.
- Виды эффектов (список расширяется данными): мгновенное восстановление HP / боевой маны / резервной маны; временный бафф характеристик (оборона, крит. шанс, размер крита, урон, регенерация); очистка дебаффов или защита от них; бонус опыта; особые эффекты через обработчики (7.10).
- Группы перезарядки (7.7); бафф-зелья одной категории заменяют друг друга (ДЕФОЛТ), чтобы не было бесконечного суммирования.
- Зелья резервной маны — главный «сток» этого ресурса (связь с 7.1 и 7.4). Качество и редкость зелья влияют на силу и длительность.
- Использование: `CmdUseConsumable` (7.7) с проверкой наличия, КД и условий на сервере.

## Открытые вопросы (сквозная нумерация)

1. Как восстанавливается резервная мана вне боя? ДЕФОЛТ: медленно вне боя + расходники/алтари.
2. Растут ли максимумы пулов (200/200) от уровня и экипировки? ДЕФОЛТ: стартуют с 200, модифицируются предметами/талантами.
3. Может ли стоимость в HP убить игрока? ДЕФОЛТ: нет, остаётся минимум 1 HP.
4. Что делать при зажатых Shift+Ctrl? ДЕФОЛТ: обычный вариант.
5. Все ли навыки имеют усиленный и ослабленный варианты? ДЕФОЛТ: нет, дизайнер включает/отключает варианты в данных; без варианта применяется обычный.
9. Стартовые классы и профессии (названия, роли)? ДЕФОЛТ: Воин, Маг, Целитель; профессии: одна добывающая, одна производственная (алхимия).
25. Верхний предел обороны и базовый размер крита? ДЕФОЛТ: оборона до 75%, крит ×1,5, пределы в данных.
26. Идёт ли время баффов/зелий, пока игрок не в сети? ДЕФОЛТ: только онлайн.
