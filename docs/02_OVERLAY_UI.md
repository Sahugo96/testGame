## 7.13 Оверлей игрока (HUD): логика и меню механик

**Идея.** У каждого игрока поверх мира один общий слой интерфейса, оверлей. В центре внизу находятся активные способности, по сторонам и краям экрана: рамки персонажа и цели, мини-карта, чат и меню механик. Каждая игровая механика (персонаж, рюкзак, гильдия, арена и т.д.) — отдельное **окно**. Окно открывается кнопкой меню, горячей клавишей либо (для торговли, крафта, магазинов) взаимодействием с NPC или объектом в мире. Оверлей собирается из данных (реестр окон): новая механика добавляется записью в реестре и префабом окна, без правки каркаса.

**Зоны оверлея (по референсу):**

| Зона | Содержимое |
|---|---|
| Верх-лево | рамка игрока (HP, оба пула маны, уровень, метка лидера), рамки группы, иконки эффектов с таймерами |
| Верх-центр | рамка цели (HP, эффекты цели) |
| Верх-право | название зоны, время, мини-карта и её кнопки |
| Лево | окна чата (несколько, с вкладками) |
| Низ-центр | панели активных способностей (3 ряда по 12 слотов), расходники |
| Низ-лево | меню механик: ряд кнопок-иконок, каждая открывает своё окно |
| Низ-право | полоса опыта и системное меню (настройки и др.) |
| Право-низ | закреплённые окна (например, рюкзак) |
| Центр | окна взаимодействия и крупные окна (рынок, персонаж, гильдия) |
| Мир | ники, плашки (в том числе личных магазинов), полосы здоровья, числа урона, эмодзи-пузыри |

**Меню механик (кнопки-иконки):**
- Основной ряд (низ-лево). Подтверждено: окно персонажа (портрет), гильдия (синие человечки), арена (два скрещённых меча), рюкзак/инвентарь. Остальные кнопки ряда (книга, звезда и др.) предполагаются как книга умений/журнал и достижения, требуют уточнения.
- Системное меню (низ-право): настройки (шестерёнка) и ещё несколько кнопок, назначение которых требует уточнения.
- Кнопки показывают подсказку (название и горячая клавиша) и **бейджи** событий: новые предметы, приглашения, непрочитанное.

**Общие правила окон:**
- Состояния: закрыто / открыто / свёрнуто. Повторное нажатие кнопки или клавиши закрывает окно; Esc закрывает верхнее окно.
- Окна перетаскиваются, имеют крестик и ручки сворачивания по краям. Позиция и размер сохраняются отдельно для каждого персонажа (7.7).
- Одновременно открыто несколько окон, есть фокус и порядок слоёв.
- Окна взаимодействия с NPC (рынок, магазин, крафт) закрываются при отходе от NPC и при начале боя (ДЕФОЛТ).
- Доступность по состоянию: часть окон и действий блокируется в бою, подземелье или PvP (флаги в реестре). Блокировка в интерфейсе только для удобства, сервер проверяет всё независимо.
- Разблокировка: механики открываются по уровню, квесту, классу или состоянию гильдии; недоступные кнопки затемнены с подсказкой условия (ДЕФОЛТ).
- **Подписка на данные:** данные окна запрашиваются при открытии и обновляются только пока окно открыто. Это экономит трафик при большом числе игроков.
- Перетаскивание между окнами и панелями (из книги умений и рюкзака на панели навыков и расходников) идёт через единый сервис; ссылки только по ID, сервер проверяет.
- Окно не содержит игровой логики: оно показывает данные модели и отправляет команды серверу.

**Реестр окон (данные):**

```
HudWindowDefinition {
  Id, NameKey, Icon
  MenuZone: BottomLeft | BottomRight | None     // где кнопка в меню
  MenuOrder, HotkeyAction                        // переназначаемое действие ввода
  OpenedBy: Menu | Npc | WorldObject | Event
  UnlockCondition                                // уровень, квест, класс, гильдия
  AvailableIn: Combat | Instance | Pvp           // флаги разрешённых состояний
  Singleton: bool
  PrefabRef                                      // Addressables
  BadgeSource?                                   // откуда берутся бейджи
  DataSubscription                               // какие данные запрашивать при открытии
}
```

**Горячие клавиши не зафиксированы:** каждое действие (кнопки меню и окна, слоты панелей, клавиши-модификаторы вариантов навыков) игрок назначает сам в настройках (7.6), с обнаружением конфликтов. Раскладка по умолчанию лишь стартовая и подбирается в модуле 7 (ДЕФОЛТ: Shift и Ctrl — модификаторы вариантов навыков, дополнительные ряды панелей — Alt+цифра, как в референсе; без конфликтов с клавишами движения и слотов).

**Реализация:** uGUI + TextMeshPro. Компоненты: `HudRoot` (Canvas Scaler), `HudZone` (якоря), `WindowManager` (открытие, закрытие, фокус, стек), `WindowRegistry` (Addressables), `MenuBar` (строится из реестра), `DragDropService`, `BadgeService`. Разделение вид/модель (View–ViewModel): окна не обращаются к сети напрямую.

**Правила UI-кода (новое в v2, из `ui-system.mdc`, адаптировано):**
- 🔴 UI-скрипты клиента лежат в `Assets/_Project/Scripts/Client/UI/`. *(адаптировано: исходное правило указывало `Scripts/UI/`; у нас UI — часть клиентской сборки `Game.Client`)*
- 🟠 View отображает состояние; игровые правила в UI не живут. Связь с системами через events или presenters (у нас ViewModel).
- 🟠 Не использовать `FindObjectOfType` в runtime-коде UI: serialized references или задокументированный service locator.
- 🟡 По возможности отделять UI-строки и layout от core gameplay-сборок (строки только через ключи локализации, `01_DEV_PLAN.md`, раздел 6).
- Уровни 🔴🟠🟡🟢 описаны в `01_DEV_PLAN.md`, раздел 6.

**Персонализация оверлея:** состав и порядок кнопок меню (скрыть, показать, переставить), позиции и масштаб окон хранятся на сервере для каждого персонажа и редактируются в режиме редактирования HUD (7.7).

## 7.7 Панели быстрого доступа (HUD)

**Общее:**
- Режим редактирования HUD: перемещение, масштаб, прозрачность, привязка к якорям/сетке, блокировка, сброс к стандарту.
- Раскладка и содержимое панелей сохраняются на сервере для каждого персонажа.
- Слоты хранят только ссылки (ID навыка, предмета, комплекта, эмодзи). Любое использование идёт через серверные команды и валидируется на сервере.
- Корректная работа на разных разрешениях и соотношениях сторон (якоря, Canvas Scaler), включая 4K.

**А. Панель активных навыков**
- Несколько панелей (ДЕФОЛТ: 3 панели по 12 слотов; основная видна всегда); назначение перетаскиванием из книги навыков; переключаемые наборы раскладок.
- Слот показывает: иконку, клавишу, перезарядку, GCD, нехватку ресурса (разная подсветка для основной маны, резервной маны и HP), недоступность из-за дальности/цели.
- Предпросмотр вариантов: при зажатом Shift/Ctrl иконка и подсказка меняются на соответствующий вариант с его стоимостью и эффектом.
- Буфер ввода (ДЕФОЛТ: ~0,3 с): нажатие чуть раньше конца перезарядки ставится в очередь.
- Использование: `CmdUseSkill` с текущим модификатором.

**Б. Панель расходников**
- Слоты со стаками (ДЕФОЛТ: 8 слотов), счётчик, использование по клавише или клику.
- Группы перезарядки (например: зелья здоровья, зелья основной маны, зелья резервной маны): у каждой группы свой КД.
- Авто-подстановка: когда стак закончился, слот подхватывает такой же предмет из инвентаря.
- Зелья резервной маны визуально выделены; при полном пуле использование блокируется (ДЕФОЛТ), чтобы не тратить впустую.
- Использование: `CmdUseConsumable` с проверкой наличия, КД и условий на сервере.

**В. Быстрая смена экипировки**
- Комплекты (loadouts): ДЕФОЛТ 5 штук; сохранить текущую экипировку в комплект, переключать клавишей, кликом или колесом.
- Предпросмотр изменения характеристик, включая максимумы обоих пулов маны.
- Смена выполняется сервером одной операцией; если предмета нет (продан, потерян), комплект применяется частично, игрок получает предупреждение.
- Ограничения в бою (решение разработчика, вопрос 10): менять можно **только оружие**, броню — нельзя (комплект в бою применяется только в части оружия). Основная рука (одноручное и двуручное оружие — по одним правилам): после смены перезарядка 15 с, затем «откат» 5 с; смена во время отката даёт блок на 60 с без последующего отката (подтверждено, вопрос 56: 15 с смена запрещена → 5 с смена разрешена, но даёт блок 60 с → дальше свободно). Вторая рука (щит, второе оружие и т.п.): перезарядка всегда 5 с, без отката. Вне боя — без КД (ДЕФОЛТ). После смены пересчитываются максимумы ресурсов; текущие значения обрезаются до нового максимума и не растут сами (ДЕФОЛТ).
- Опциональная привязка комплекта к раскладке панели навыков (ДЕФОЛТ: выключена).
- Использование: `CmdSwapLoadout { loadoutId }`.

**Г. Эмодзи**
- В чате: шорткоды (`:smile:`), окно выбора с поиском и недавними; отображение через спрайтовый атлас TextMeshPro. Лицензию выбранного набора эмодзи проверить до использования.
- Панель быстрых эмодзи: радиальное меню или слоты на клавишах (ДЕФОЛТ: 8 слотов).
- Эмодзи-пузыри над персонажем (1–3 с), видны только игрокам в зоне интереса; анимации-эмоции персонажа добавляются позже.
- Сервер: клиент отправляет только ID эмодзи из белого списка (`CmdEmoji { emojiId }`), лимит частоты (ДЕФОЛТ: 1 раз в 2 с), никакого произвольного контента. Игрок может скрыть чужие эмодзи в настройках чата.

## 7.6 Настройки пользователя

**Меню настроек (категории):**

| Категория | Содержимое | Хранение |
|---|---|---|
| Графика | пресет качества (Низкое/Среднее/Высокое/Ультра, автоопределение при первом запуске), разрешение, режим окна, VSync, лимит FPS, масштаб рендера, тени, сглаживание, дальность прорисовки, плотность VFX, лимит видимых ников/эффектов других игроков, постобработка | локально (устройство) |
| Звук | общая громкость, музыка, эффекты, интерфейс, окружение; звук при свёрнутом окне | локально (устройство) |
| Управление | переназначение клавиш, клавиши-модификаторы вариантов навыков (Shift/Ctrl), чувствительность камеры, инверсия осей, зум, автобег | сервер (аккаунт) |
| Интерфейс | масштаб UI, прозрачность панелей, размер шрифта, режим редактирования HUD, числа урона, ники, полосы здоровья | сервер (персонаж/аккаунт) |
| Игровые | автотаргет, автолут, подтверждения действий, поведение камеры | сервер (аккаунт) |
| Чат | фильтры каналов, фильтр лексики, показ эмодзи, размер текста | сервер (аккаунт) |
| Доступность | режимы для дальтоников, уменьшение вспышек и тряски камеры, крупный текст, субтитры | сервер (аккаунт) |
| Язык | язык интерфейса | сервер (аккаунт) |
| Диагностика | показ FPS, пинга, потерь пакетов | локально (устройство) |

**Правила:**
- Кнопки «Применить» / «Отмена» / «По умолчанию» (для категории и для всех настроек).
- Изменение разрешения и режима окна требует подтверждения с автооткатом через ~15 с.
- Горячие клавиши: Input Actions + rebinding API, обнаружение конфликтов (предупреждение: заменить или поменять местами), зарезервированные клавиши (например, Esc), текущая клавиша отображается в подсказках и на слотах панелей.
- Серверные настройки хранятся как версионированный JSON-документ (`schemaVersion`): ограничение размера, валидация схемы и значений на сервере, миграция версий при обновлениях. Локальный кеш + загрузка при входе; при конфликте побеждает последнее изменение (ДЕФОЛТ).
- Настройки не влияют на честность игры: лимиты видимости ников/эффектов меняют только отрисовку на клиенте.
- Профили настроек (например, «Рейд» и «Соло»): на срезе один профиль, архитектура допускает несколько (ДЕФОЛТ).

## Открытые вопросы (сквозная нумерация)

10. Можно ли менять экипировку в бою? **РЕШЕНО (v5):** в бою — только оружие, броню нельзя; основная рука (одно- и двуручное оружие): перезарядка 15 с + «откат» 5 с, смена во время отката → блок 60 с без отката; вторая рука: всегда 5 с без отката.
11. Где хранить настройки? **РЕШЕНО (v4):** графика и звук — локально на устройстве; управление, интерфейс, игровые, чат, доступность — на сервере.
12. Размеры панелей? ДЕФОЛТ: навыки 3×12, расходники 8, комплекты экипировки 5, быстрые эмодзи 8. **Отложено разработчиком:** вернуться позже; до решения действует ДЕФОЛТ.
13. Набор эмодзи и лимит частоты? ДЕФОЛТ: белый список на старте (около 40), не чаще 1 раза в 2 с; набор с подходящей лицензией. **Отложено разработчиком:** вернуться позже; до решения действует ДЕФОЛТ.
27. Назначение иконок «книга», «звезда» и кнопок правого меню (по скриншоту не ясно)? ДЕФОЛТ: книга — книга умений и таланты, звезда — достижения. **Отложено разработчиком:** вернуться позже; до решения действует ДЕФОЛТ.
28. Какие кнопки меню нужны на вертикальном срезе? ДЕФОЛТ: персонаж, рюкзак, книга умений, настройки; кнопки ещё не реализованных механик не показываются. **Отложено разработчиком:** вернуться позже; до решения действует ДЕФОЛТ.
56. Хронология смены оружия: верно ли, что после смены 15 с смена запрещена, затем 5 с смена разрешена, но даёт блок на 60 с, а после этих 5 с — снова свободна? **РЕШЕНО (v6):** да.
86. Решения среза для модуля 17, которых нет в документах? ДЕФОЛТ: в проекте два уровня качества (Mobile, PC), поэтому пресеты «Низкое / Среднее / Высокое / Ультра» — данные `config.GraphicsPresets`: уровень качества по имени плюс масштаб рендера, дальность теней, MSAA и LOD bias (ставятся на копию URP-ассета, сам ассет проекта не меняется); при первом запуске пресет выбирается по видеопамяти; графика хранится в файле `settings_local.json`; режимы окна — без рамки, полный экран, в окне; ограничение кадров — 30 / 60 / 120 / 144 / без ограничения; новое разрешение или режим окна откатываются через 15 с без подтверждения; из диагностики — только счётчик FPS. Переназначаются: движение (только WASD, стрелки остаются), следующая цель, чат, Shift/Ctrl вариантов навыков, 12 ячеек навыков и горячие клавиши окон; мышь и Esc зарезервированы; при конфликте — «Заменить» (у другого действия клавиша снимается), «Поменять» или «Отмена»; в аккаунте хранятся только изменённые клавиши. Камера: чувствительность 0,2–3, скорость приближения 0,2–3, инверсия по вертикали. Интерфейс: масштаб 75–150%, непрозрачность HUD 30–100% (вместе с текстом; окна не прозрачнеют), числа урона, имена и полосы здоровья над персонажами. Игровые: автоподбор (как раньше) и вкладки чата. Не сделаны в срезе: звук (звуков в игре ещё нет), язык (вопрос 81), фильтр лексики, доступность, режим редактирования HUD (модуль 18), автобег, автотаргет, подтверждения действий, профили настроек (один профиль), местный кеш настроек аккаунта до входа.
