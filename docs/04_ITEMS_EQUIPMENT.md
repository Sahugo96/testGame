## 7.9 Предметы: классы, уровни, редкость, слоты

**Определение и экземпляр:**

```
ItemDefinition {
  Id, NameKey, Icon
  Category            // Оружие | Одежда/броня | Украшение | Расходник | Материал | Материал улучшения | Ингредиент слота | Катализатор | Квестовый | Лут
  ClassRestriction?   // каким классам персонажей доступен (пусто = всем)
  ItemLevel           // уровень предмета (сила)
  RequiredLevel       // с какого уровня персонажа можно использовать
  Rarity              // см. таблицу ниже
  BaseStats, AffixPools
  UpgradeRules?       // таблица улучшения (раздел 7.14.1); пусто = предмет нельзя улучшать
  SocketRules { AllowedSocketTypes[], MaxSockets? }   // MaxSockets ≤ SocketCap слота экипировки (7.9.1)
  Binding: None | OnPickup | OnEquip
  GlobalUnique: bool  // true только у Божественных
  StackSize
}

ItemInstance {        // хранится в БД, создаётся только сервером
  InstanceId (GUID), DefinitionId
  RolledStats, Affixes
  Sockets: [{ Type, IsOvercap, InsertedIngredientId? }]
  UpgradeLevel        // уровень улучшения, по умолчанию 0 (раздел 7.14.1)
  BoundTo?, CreatedBy?, CreatedAt
}
```

**Рюкзак (срез v11, запрос разработчика):** отсеки-вкладки «Экипировка» (оружие, броня, украшения), «Расходники», «Лут» (трофеи с мобов), «Ресурсы» (материалы, материалы улучшения, ингредиенты слотов, катализаторы), «Квестовые»; у каждого своя вместимость. Соответствие категорий отсекам и размеры — данные (`bag_sections.json`).

**Реализация: компоненты-свойства (решение разработчика, `01_DEV_PLAN.md` §11, v9).** Поведение предмета задаётся набором компонентов в данных, а не жёстким набором полей; одни компоненты требуют других:

| Компонент | Требует | Смысл |
|---|---|---|
| `Equipment` | — | предмет можно надеть |
| `EquipSlot` (`SlotType`: Head, Body, Hands, Legs, Feet, Ring, Necklace, MainHand, OffHand; `Hands`) | `Equipment` | какой слот занимает; двуручное оружие освобождает вторую руку |
| `Armor` (`ArmorType`) | `Equipment`, `EquipSlot` | тип брони, проверяется по классу |
| `Weapon` (`WeaponType`) | `Equipment`, `EquipSlot` | вид оружия, проверяется по классу |
| `Stats` (список `StatModifier`) | `Equipment` | бонусы, пока предмет надет (`SourceId` = экземпляр) |
| `Consumable` (эффект, ресурс, количество, группа перезарядки) | — | использование тратит единицу |
| `Stackable` (`MaxStack`) | — | складывается в одной ячейке |

Поля `BaseStats` и `StackSize` из модели выше реализуются компонентами `Stats` и `Stackable`; `AffixPools`, `UpgradeRules`, `SocketRules` появятся отдельными компонентами в модулях 11–12. Новое свойство = регистрация компонента в `ItemComponentRegistry` без правки ядра (7.10).

**Редкость (по возрастанию):**

| # | Редкость | Особенности (стартовые гипотезы для настройки) |
|---|---|---|
| 1 | Обычный | без аффиксов, слотов обычно нет |
| 2 | Необычный | 1 аффикс |
| 3 | Редкий | 2 аффикса |
| 4 | Мифический | 3 аффикса, повышенный шанс слотов |
| 5 | Легендарный | 4 аффикса и уникальный эффект. **Истинные** легендарки выпадают только с легендарных боссов (редкий шанс, без лимита экземпляров); кузнецы могут ковать их **реплики**: истинную легендарку можно разобрать на 5 рецептов реплики; реплика на 10% слабее по всем параметрам (вопросы 22, 61) |
| 6 | Божественный | ровно один экземпляр на все серверы, уникальные свойства |

Цвета, иконки рамок и эффекты по редкости хранятся в данных.

**Слоты (сокеты) и ингредиенты:**
- Предмет может иметь слоты, в которые вставляются ингредиенты: ядра монстров, души монстров, уникальные сверхредкие минералы и **рукотворные ядра**. Рукотворные ядра создаёт отдельная небоевая профессия, объединяя несколько ядер и преобразуя их свойства (уровень, характеристики, дебаффы) — решение разработчика, вопрос 14. «Ремесленник» в документах — общее название небоевых профессий.
- Слот имеет тип (ядро, душа, минерал, универсальный); вставляется ингредиент подходящего типа.
- Ингредиент — предмет категории «Ингредиент слота». Его эффекты (характеристики, шанс эффекта, модификатор навыка, модификатор ресурсов, например +максимум резервной маны) входят в пересчёт характеристик предмета.
- Количество слотов ограничено лимитом `SocketCap`. Он хранится в одном месте — в `EquipmentSlotDefinition` (7.9.1) и одинаков для всех слотов группы (проверяет валидатор), поэтому фактически задаётся по категории. Пример: у одежды лимит 1 слот. Предмет может сузить лимит своим `MaxSockets` (временно (ДЕФОЛТ), вопрос 47).
- Слоты создаются при крафте: их число зависит от рецепта, уровня профессии, качества материалов и катализаторов. Выпавшие предметы в основном без слотов; с малым шансом (данные таблицы лута) выпадают со слотами в пределах лимита (вопрос 19).
- Вставка — серверная операция на станции/через интерфейс; ингредиент расходуется и становится частью предмета. Обычно извлечь его нельзя, замена уничтожает прежний ингредиент. Ремесленник с достаточным мастерством может попытаться извлечь ингредиент с шансом; при неудаче ингредиент разрушается (вопрос 16). Извлечение — серверная атомарная операция с записью в аудит-лог.
- **Особый слот сверх лимита** (`IsOvercap = true`) создаётся только особыми предметами (например, «Искра Гефеста») и не учитывается в лимите. Обычными способами создать его нельзя.

**Божественные предметы:**
- Один экземпляр на все серверы (все миры). Реализация: реестр уникальных предметов в центральной БД с ограничением уникальности на уровне базы; выдача через атомарную транзакцию.
- Пока экземпляр существует (у игрока, в хранилище, в мире), источник не выдаёт второй.
- Нельзя уничтожить, продать NPC или удалить (ДЕФОЛТ). Если владелец удалил персонажа или неактивен слишком долго (30 дней, решение разработчика), предмет возвращается в мир через заданный источник.
- Все операции с божественными предметами пишутся в аудит-лог; у администраторов есть инструмент восстановления.
- Божественный предмет нельзя вставить в слот как ингредиент: ингредиент становится частью предмета и уничтожается при замене, а божественный предмет уничтожать нельзя (ДЕФОЛТ, вопрос 48).
- Способ получения задаётся данными (уникальный босс или событие). Божественные предметы не расходуются и **привязываются к персонажу при получении** (`Binding = OnPickup`): передать или продать их нельзя (вопросы 18, 35).
- **Пример: «Искра Гефеста»** (катализатор крафта): +10 процентных пунктов к шансу успешного создания предмета; при успешном создании 5% шанс получить особый слот сверх лимита (например, второй слот в одежде при лимите 1). Как все божественные предметы, не расходуется и привязан к персонажу (передать нельзя). Значения лежат в данных предмета.

## 7.9.1 Виды экипировки (слоты, типы брони и оружия)

**Принцип:** этот раздел описывает **виды** предметов (слоты, типы брони и оружия), а не отдельные предметы. Конкретные шлемы, мечи и т.д. — это данные (`ItemDefinition`), они добавляются без правки кода (7.10).

**Слоты экипировки:**

| Группа | Слот | Примечание |
|---|---|---|
| Одежда | Голова (шлем) | основной слот |
| Одежда | Тело (доспех) | основной слот |
| Одежда | Руки (перчатки) | основной слот |
| Одежда | Ступни (ботинки) | основной слот |
| Одежда | Ноги (штаны, поножи) | основной слот |
| Одежда | Плащ, плечи, пояс | опциональные, добавляются данными позже |
| Украшения | Кольца (2 или 4 — зависит от класса, `ClassDefinition.EquipmentRules`), ожерелье | решение разработчика, вопрос 36 |
| Оружие | Основная рука | оружие |
| Оружие | Вторая рука | щит, магический фокус или оружие второй руки |

**Типы брони (вес/материал)**, ДЕФОЛТ: тканевая, кожаная, латная. Тип задаёт уклон характеристик (гипотеза для баланса): латная даёт больше обороны (% снижения урона) и здоровья, кожаная — баланс, тканевая — больше ресурсов (пулы маны) и крита. Допустимые классам типы брони задаются в `ClassDefinition.EquipmentRules` (7.3).

**Виды оружия** (список расширяется данными):
- Одноручное: меч, топор, булава, кинжал.
- Двуручное: меч, топор или молот, древковое (копьё, алебарда).
- Дальнобойное: лук, арбалет.
- Магическое: посох (двуручный), жезл (одноручный).
- Вторая рука: щит, магический фокус или книга.

Параметры типа оружия: число рук, вид атаки (ближняя, дальняя, магическая), дальность, базовая скорость атаки, допустимые классы. Двуручное оружие занимает обе руки.

**Правила слотов:**
- `SocketCap` задаётся в `EquipmentSlotDefinition` и одинаков для всех слотов группы: у одежды 1 слот (задано проектом). Для оружия и украшений значения лежат в данных (ДЕФОЛТ-гипотеза: оружие 2, украшения 0).
- Направленность характеристик по слотам (ДЕФОЛТ): оружие — урон и крит; одежда — оборона и здоровье; украшения — крит. шанс, размер крита и ресурсы (пулы маны). Конкретные числа — данные и баланс.
- Требования к предмету: `RequiredLevel`, `ClassRestriction`, тип брони или оружия (7.3).

**Модель данных:**

```
EquipmentSlotDefinition { Id, Group, AllowedCategories, AllowedTypes, SocketCap, VisualAnchor }
ArmorTypeDefinition     { Id, NameKey, StatBias }
WeaponTypeDefinition    { Id, NameKey, Hands, AttackKind, Range, AttackSpeed }
ItemDefinition          // получает: EquipmentSlot, ArmorType?, WeaponType?
```

**Внешний вид:** персонаж собирается из частей по слотам (шлем, доспех, перчатки, ботинки, оружие); у предмета есть визуальная часть. Скрытие частей и косметические образы — позже.

**Не путать:** комплект экипировки (loadout, 7.7) — сохранённая раскладка для быстрой смены; бонусы за комплект (set bonuses) входят в проект (вопрос 38), косметических образов не будет.

**Рынок:** категории «Оружие» и «Одежда» (7.14.3) строятся по этим видам.

## 7.11 Реестр легендарных предметов (таблица для всех игроков)

- Игровое окно, доступное всем игрокам из меню (веб-версия — позже, ДЕФОЛТ).
- Содержимое: только божественные предметы (решение разработчика, вопрос 23): иконка, название, редкость, описание уникального эффекта, лимит экземпляров, текущие обладатели (имя персонажа, класс, гильдия, мир/сервер) и дата получения. Колонка «гильдия» появляется вместе с гильдиями (раздел 13 «Отложено»). Ещё не найденные показываются как «Не найден», подробности раскрываются после первого получения (ДЕФОЛТ).
- Поиск и фильтры: по названию, редкости, классу, обладателю; сортировка по дате получения.
- Лента событий: последние получения и потери предметов (ДЕФОЛТ: включена). История прежних обладателей («зал славы») — опционально.
- **Источник данных:** реестр — это представление (view) поверх таблицы экземпляров предметов в центральной БД, а не отдельная копия. Так он не может рассинхронизироваться с реальными владельцами. Запись: `LegendaryRegistryEntry { itemDefId, instanceId, ownerCharacterId, realmId, acquiredAt }`.
- Клиенты запрашивают данные по требованию (пагинация, кеш на стороне сервера с TTL около 1 мин), а не получают рассылку.
- Приватность и безопасность: показываются имя персонажа, класс, гильдия и мир, скрыть их владелец не может; **локация и онлайн-статус не показываются**, чтобы владельца было сложнее выслеживать. Ограничение частоты запросов к реестру.

## 7.14.1 Улучшение предметов (`UpgradeLevel`)

- `ItemInstance.UpgradeLevel` (по умолчанию 0) — уровень улучшения. Повышение уровня усиливает базовые характеристики предмета по кривой из таблицы улучшения (`UpgradeRules`, данные). Влияние идёт через `StatModifier` (SourceId = предмет), раздел 7.12.
- **Улучшать могут только кузнецы.** Операция доступна игроку с профессией «Кузнец» на станции (наковальня/кузница). Максимальный уровень (около +10), который кузнец может применить, зависит от уровня его профессии и мастерства (решение разработчика, вопрос 31).
- Таблица улучшения (данные): максимум уровня по категории и редкости (стартовая гипотеза: +10), требуемый уровень профессии на каждый шаг, материалы (предметы категории «Материал улучшения»), шанс успеха по уровням (убывает с ростом уровня), стоимость в валюте.
- **Срез v11 (запрос разработчика):** попытка стоит 1 осколок философского камня; шанс успеха 100% для +0→+1 и на 5% меньше на каждом следующем шаге (55% для +9→+10); максимум +10; каждый уровень даёт +10% к бонусам предмета. Таблица — данные (`upgrade_rules.json`); компонент предмета `Upgradeable` ссылается на неё. Пока улучшать может любой персонаж (решение разработчика, вопрос 66), шанс разрушения 0 (решение разработчика, вопрос 65).
- Неудача (решение разработчика, вопрос 31): материалы теряются, уровень улучшения снижается, и есть шанс **полного разрушения** предмета. Специальные дополнительные ингредиенты полностью убирают шанс разрушения. Результат фиксируется на сервере до отправки клиенту, чтобы отключение посреди операции не позволяло избежать поломки.
- Улучшение чужого предмета: игрок передаёт предмет и оплату через окно заказа с **эскроу** (сервер удерживает предмет и оплату до выполнения), кузнец улучшает на станции, сервер возвращает предмет владельцу и переводит оплату кузнецу (ДЕФОЛТ). Кузнец не может присвоить чужой предмет при заказе через эскроу. Помимо эскроу игроки могут договориться через обычный обмен (модуль 14): заказчик передаёт ресурсы или деньги, кузнец создаёт и отдаёт предмет — или обманывает; это осознанная часть «живого» мира, система такие сделки не страхует (решение разработчика, вопрос 30). Реализуется в модуле 20 (нужны БД и торговая инфраструктура); в модуле 12 кузнец улучшает свои предметы.
- Команда: `CmdUpgradeItem { itemInstanceId, stationId }`. Сервер проверяет профессию, уровень, станцию, материалы и валюту; бросок шанса делается только на сервере; операция транзакционная и пишется в аудит-лог.
- Улучшение не меняет слоты, редкость и аффиксы. Легендарные предметы улучшать можно, божественные — нельзя. Вместо улучшения у божественного предмета растёт **«связь»** — своя шкала опыта, которая повышает его характеристики (через `StatModifier`, `SourceId` = предмет). Опыт связи даёт использование предмета: боевым — убийства монстров, ремесленным (например, «Искра Гефеста») — крафт (решение разработчика, вопрос 32). Когда предмет возвращается в мир, связь сбрасывается: новый владелец начинает с нуля (вопрос 55).
- `UpgradeLevel` отображается на иконке (+N) и индексируется как фильтр «Улучшения» на рынке.

## Открытые вопросы (сквозная нумерация)

14. Типы ингредиентов для слотов? **РЕШЕНО (v4):** ядра монстров, души монстров, уникальные сверхредкие минералы и рукотворные ядра (их создаёт отдельная небоевая профессия, объединяя ядра); «ремесленник» — общее название небоевых профессий.
15. «Классы предметов» — это категории предметов или ограничение по классу персонажа? **РЕШЕНО (v3):** категория обязательна (например, шлем); ограничение по классу персонажа опционально: один класс, несколько или все.
16. Можно ли извлекать вставленные ингредиенты? **РЕШЕНО (v4):** обычно нельзя; ремесленник с достаточным мастерством может извлечь с шансом, при неудаче ингредиент разрушается.
17. Что происходит с божественным предметом при удалении персонажа или долгой неактивности владельца? **РЕШЕНО (v3):** предмет возвращается в мир через свой источник; срок неактивности — 30 дней.
18. «Искра Гефеста»: расходуется ли при использовании, можно ли передавать, как получить? **РЕШЕНО (v4):** все божественные предметы не расходуются и привязываются к персонажу при получении; источник — уникальный босс или событие; «Искру Гефеста» передать нельзя.
19. Какая доля мобов даёт слоты и что при неудаче крафта? **РЕШЕНО (v4):** выпавшие предметы в основном без слотов, с малым шансом — со слотами; при неудачном крафте все ингредиенты уничтожаются (божественные катализаторы не расходуются).
22. Сколько экземпляров может быть у легендарного предмета? **РЕШЕНО (v6):** у истинных легендарок лимита экземпляров нет, их нельзя скрафтить — только редкий дроп с легендарных боссов; кузнец может ковать реплики легендарок (шанс успеха — данные, вероятно ниже, чем в вопросе 8).
23. Показывать ли в таблице божественные предметы и можно ли скрыть владельца? **РЕШЕНО (v3):** в таблице только божественные предметы; имя владельца и его гильдию скрыть нельзя; локация и онлайн-статус не показываются.
24. Нужна ли веб-версия таблицы? ДЕФОЛТ: позже, после игрового окна. **Отложено разработчиком:** вернуться позже; до решения действует ДЕФОЛТ.
30. Может ли кузнец улучшать предметы других игроков? **РЕШЕНО (v3):** да, через заказ с эскроу (модуль 20); кроме того, возможен обычный обмен ресурсами или деньгами без гарантий — с риском обмана, это осознанная часть игры.
31. Максимальный уровень улучшения и последствия неудачи? **РЕШЕНО (v5):** максимум около +10, зависит от уровня и мастерства кузнеца; при неудаче теряются материалы, уровень снижается, есть шанс полного разрушения предмета; специальные ингредиенты убирают шанс разрушения.
32. Можно ли улучшать легендарные и божественные предметы? **РЕШЕНО (v4):** легендарные можно, божественные нельзя; у божественных растёт «связь» (опыт за использование: убийства — для боевых, крафт — для ремесленных), она повышает характеристики.
36. Состав слотов экипировки (есть ли ноги, плечи, плащ, пояс, сколько колец)? **РЕШЕНО (v4):** шлем, доспех, перчатки, штаны, ботинки, кольца (2 или 4 — зависит от класса), ожерелье, оружие разных типов и классов (одноручное, двуручное, вторая рука — щит и т.п.).
37. Лимиты слотов (сокетов) для оружия и украшений? ДЕФОЛТ: оружие 2, украшения 0; у одежды 1 (задано). **Отложено разработчиком:** вернуться позже; до решения действует ДЕФОЛТ.
38. Нужны ли бонусные наборы и косметические образы? **РЕШЕНО (v3):** бонусы за комплект — да; косметические образы — нет.
47. Где хранится лимит сокетов? ДЕФОЛТ: только в `EquipmentSlotDefinition.SocketCap` (одинаков в группе, проверяет валидатор); предмет может сузить его через `SocketRules.MaxSockets`. (новое в v2)
48. Можно ли вставлять божественный предмет в слот как ингредиент? **РЕШЕНО (v3):** нет.
55. Сбрасывается ли «связь» божественного предмета, когда он возвращается в мир (30 дней неактивности, вопрос 17)? **РЕШЕНО (v5):** да, новый владелец начинает с нуля.
57. Кто несёт риск, если при заказе улучшения через эскроу (модуль 20) предмет заказчика разрушился? ДЕФОЛТ: заказчик; система не компенсирует, но в заказе можно потребовать использовать страхующий ингредиент. (новое в v5)
61. Чем реплика легендарного предмета отличается от истинного? **РЕШЕНО (v8):** истинную легендарку можно разобрать на 5 рецептов реплики; реплика на 10% слабее оригинала по всем параметрам.
65. Шанс разрушения предмета при неудачном улучшении (вопрос 31): с какого уровня и какой? Защитные ингредиенты (полностью убирают шанс)? **РЕШЕНО (v10):** при неудачной заточке уровень падает на 1, предмет не разрушается — шанс разрушения пока 0.
66. Кто может улучшать до появления профессий (модуль 12)? **РЕШЕНО (v10):** пока улучшать может любой персонаж у наковальни (профессий ещё нет).

## Рекомендации

15. **Антидюп и аудит предметов:** GUID экземпляра создаёт только сервер, операции с предметами транзакционные, журнал всех передач, лута, крафта и вставок. Это особенно важно для божественных предметов: из-за единственного экземпляра ошибка может создать дубликат или потерять предмет навсегда.
16. **Центральный реестр уникальных предметов:** отдельная таблица с ограничением уникальности, доступ из любой зоны и мира, инструмент восстановления для администраторов.
20. **Баланс уникальных эффектов** проверять симулятором боя и лимитами валидатора до включения легендарных предметов в игру.
