## 7.4 Профессии

**Типы:**
- **Добывающие** (например, горное дело, травничество): добыча из узлов в мире.
- **Производственные** (например, кузнечное дело, алхимия): крафт предметов по рецептам.
- (Конкретный список профессий не утверждён; на срезе — одна добывающая и одна производственная.)

**Модель данных:**

```
ProfessionDefinition { Id, NameKey, Type, MaxLevel, XpCurve }
Recipe { Id, Profession, RequiredLevel, Inputs[], Outputs[], Station?, CraftTime, XpReward }
GatheringNode { Id, Profession, RequiredLevel, RequiredTool?, LootTable, RespawnTime }
```

**Правила:**
- Добыча и крафт полностью на сервере: проверка дистанции, уровня, инструментов, ресурсов, лимитов по частоте (защита от ботов).
- Лимит основных профессий на персонажа: 2 (ДЕФОЛТ).
- Связь с боевой системой: алхимия делает расходники, в том числе **восстанавливающие резервную ману**. Это естественный «поглотитель» ресурсов и причина существования профессий.
- Экономика: для каждого ресурса продумать «источник» (откуда берётся) и «сток» (куда уходит), чтобы не было инфляции предметов.
- Крафт: у каждого рецепта есть шанс успеха (зависит от уровня профессии, качества ингредиентов и катализаторов). Результат может получить слоты под ингредиенты (раздел 7.9). Катализаторы (например, «Искра Гефеста») меняют шанс успеха и исходы. При неудаче часть материалов теряется (ДЕФОЛТ); нерасходуемые катализаторы (например, «Искра Гефеста», вопрос 18) не теряются.
- **Улучшение предметов** (повышение `UpgradeLevel`) выполняют только игроки с профессией «Кузнец» (раздел 7.14.1).

## 7.14.2 Кошелёк валют

```
CurrencyDefinition { Id, NameKey, Icon, Kind: Soft | Premium | Token, Scope: Character | Account, Tradable, Cap }
Wallet { Balances: { CurrencyId -> long } }
```

- Валюты задаются данными, новые добавляются без правок кода (7.10). Золото: Soft, на персонажа, торгуется. Вторая валюта (ДЕФОЛТ): на аккаунт, не торгуется на рынке; название и роль определить позже.
- Баланс — целое число (`long`), не отрицательный, с верхним пределом (`Cap`). Начисление сверх `Cap` отклоняет всю транзакцию; валюта из письма в этом случае остаётся во вложении, пока не освободится место (ДЕФОЛТ, вопрос 49).
- Любое изменение — серверная атомарная транзакция `Transact(debits[], credits[], idempotencyKey)`: либо все проводки, либо ни одной. Повторная отправка с тем же ключом не списывает дважды. Каждая проводка пишется в аудит-лог.
- Окно рюкзака показывает все валюты.
- Платные (Premium) валюты, их продажа и обмен за реальные деньги: модель монетизации решается отдельно и в вертикальный срез не входит; она потребует учёта правил платёжных систем и законодательства. Архитектура кошелька это допускает.

## 7.14.3 Торговля: личные магазины, рынок, почта (модуль 20)

*Личные магазины:*
- Игрок открывает лавку в разрешённой торговой зоне: задаёт название (проверка длины и лексики), выставляет предметы из рюкзака с ценой за штуку. Над персонажем появляется плашка с иконкой монеты и названием.
- Выставленный предмет переносится в серверный лот (витрину): его нельзя продать дважды или использовать, пока он выставлен.
- ДЕФОЛТ: лавка работает, пока игрок онлайн и находится на месте; при выходе или уходе лавка закрывается, нераспроданное возвращается в рюкзак или почту. Лимит числа лотов задаётся данными. С каждой продажи берётся налог (сток золота).
- Покупка: клик по плашке или персонажу, выбор лота и количества, подтверждение. Серверная транзакция проверяет наличие лота, версию цены (защита от подмены цены в момент покупки), валюту покупателя и место в рюкзаке.

*Рынок (глобальный поиск):*
- Окно открывается через NPC. Показывает лоты всех открытых личных магазинов: категории слева, поиск по названию, фильтры по классу, диапазону уровней, количеству слотов, уровню улучшения, редкости и цене; сортировка и пагинация; столбцы «Предмет», «Ур.», «Цена за штуку», «Магазин».
- Для этого атрибуты предмета должны индексироваться: категория, ограничение по классу, `ItemLevel`/`RequiredLevel`, число слотов, `UpgradeLevel`, редкость.
- ДЕФОЛТ: покупка прямо из окна рынка, без похода к лавке; предмет приходит в рюкзак или почту. Поиск выполняется по индексу лотов (PostgreSQL, при росте нагрузки отдельный индекс или кеш) с ограничением частоты запросов.
- Торговля на рынке и в магазинах идёт только за торгуемые валюты (ДЕФОЛТ: золото). Привязанные предметы выставлять нельзя.

*Почта:*

```
MailMessage { Id, Sender (игрок | система), Recipient, Subject, Body,
              AttachedItems[] (instanceId), AttachedCurrency[], SentAt, ExpiresAt, ReadAt, ClaimedAt,
              Type: Player | Sale | Return | System }
```

- Назначение: передача предметов и валют между игроками, системные письма (доход от продаж, возврат нераспроданного, награды, возврат при истечении срока), доставка покупки при нехватке места в рюкзаке.
- Вложение забирается атомарно: перенос владения предметом (тот же GUID), а не копирование. Срок хранения задаётся данными (ДЕФОЛТ: 30 дней, затем возврат отправителю; возвратные и системные письма повторно не истекают и хранятся до получения, вопрос 50). За отправку вложений может взиматься небольшая комиссия (в данных).
- Окно почты открывается у почтового ящика (объект в мире); новое письмо показывается бейджем на кнопке меню.

*Безопасность и экономика:*
- Все операции (выставление, покупка, отправка, получение) транзакционные, идемпотентные и пишутся в аудит-лог (кто, что, сколько, когда).
- Налоги и комиссии — стоки золота. Лимиты числа лотов и писем, ограничение частоты запросов поиска, проверка цен на аномалии.
- Подозрительные цепочки передач (много ресурсов или золота одному получателю) логируются для проверки администратором.
- Прямой обмен между игроками (окно торговли) остаётся в модуле 14.

## Открытые вопросы (сквозная нумерация)

8. Сколько основных профессий на персонажа? ДЕФОЛТ: 2.
33. Какие валюты в кошельке и какие торгуются? ДЕФОЛТ: золото (на персонажа, торгуется) и одна вторая валюта (на аккаунт, не торгуется); решение о премиальной валюте и монетизации отдельно, не на срезе.
34. Личные магазины: работают ли офлайн, где открываются, лимит лотов, налог? ДЕФОЛТ: только онлайн и на месте, в торговых зонах, лимит лотов и налог в данных.
35. Почта и торговля предметами: срок хранения, комиссия, можно ли продавать привязанные и божественные предметы? ДЕФОЛТ: 30 дней, затем возврат отправителю; привязанные нельзя; божественные можно с аудитом.
49. Что делать, если начисление превышает `Cap` кошелька? ДЕФОЛТ: транзакция отклоняется целиком; валюта из письма остаётся во вложении. (новое в v2)
50. Что с возвратными и системными письмами по истечении срока? ДЕФОЛТ: повторно не истекают и хранятся до получения, иначе вложения терялись бы или ходили по кругу. (новое в v2)

## Рекомендации

11. **Экономика:** для каждого предмета и ресурса определить источник и сток.
21. **Идемпотентные транзакции** для кошелька, торговли и почты (ключ операции), чтобы повторная отправка или обрыв связи не приводили к двойному списанию или дюпу.
22. **Эскроу** для заказов улучшения и любых сделок, где одна сторона отдаёт предмет первой.
23. **Экономические метрики:** суммарное золото в обороте, источники и стоки за сутки, медианные цены на рынке, чтобы вовремя заметить инфляцию или эксплойт.
