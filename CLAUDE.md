# CLAUDE.md — точка входа

Проект: многопользовательская RPG в духе Royal Quest на Unity 6 (URP), авторитарный dedicated server на Mirror (KCP).
Источник правды — набор документов в `docs/` (`AI_INSTRUCTIONS.md`, `00_INDEX.md`, `01`–`06`).
**Навигация по документам: `docs/MAP.md`** (разделы со строками, модуль → файлы, тип/команда → место, открытые вопросы → файл).

## Как читать контекст

- Начало модуля: прочитать **целиком** `docs/AI_INSTRUCTIONS.md`, `docs/00_INDEX.md`, `docs/01_DEV_PLAN.md` + тематические файлы модуля (`docs/MAP.md` §3). Первый ответ — по шаблону AI_INSTRUCTIONS §3.1.
- Точечная задача: `docs/MAP.md` → нужный раздел → `sed -n`. Не читать большие файлы целиком без нужды.
- Конец модуля: обновить и выдать **полные** версии изменённых документов (AI_INSTRUCTIONS §4), поднять «Версию файла».

## Не забывать (выжимка; при сомнении — первоисточник)

Процесс (AI_INSTRUCTIONS):
- Отвечать по-русски; код, имена и комментарии в коде — на английском.
- Не трогать ЗАМОРОЖЕННОЕ (01 §13); не нарушать архитектурные принципы (01 §4) и правила кода 🔴; от 🟠 — только по явному решению разработчика.
- **Не предлагать ECS/DOTS** и код в стиле Unity Entities. Серверное ядро — data-oriented на обычном C#: `struct …Data` + классы `…System`, ссылки по ID.
- Решения по ДЕФОЛТу помечать «временно (ДЕФОЛТ)». Открытые вопросы модуля задавать **одним сообщением** в начале.
- Код — целиком, с полными путями и настройками редактора; EditMode-тесты для серверной логики; в конце «как проверить» и «что прислать при ошибке».
- Не выдумывать API, классы и файлы: если не уверен — пометить «проверить компилятором/документацией».
- Не менять сквозную нумерацию разделов, модулей, вопросов. Не дублировать информацию между файлами.
- Приоритет источников (AI_INSTRUCTIONS §8): указание разработчика в чате → 01 §13 «Заморожено» → спецификация 02–06 и план → AI_INSTRUCTIONS → общие знания.

Архитектура (01 §4, §13):
- Сервер считает всё; клиент шлёт только ввод и рисует. Логика — чистый C# без Mirror. Общий код в `Game.Shared`.
- Сборки (ДЕФОЛТ, вопрос 41): `Game.Shared` без Mirror; Mirror-сообщения и обёртки — `Game.Network`; `Game.Server` не попадает в клиентский билд; `Game.Client`, `Game.Bots`. Пути от корня Unity-проекта `My project/`.
- Контент — данные (ScriptableObject + JSON/CSV), стабильные ID, обработчики эффектов по ключу (7.10). Без магических чисел.
- Экземпляры предметов создаёт только сервер (GUID); операции с предметами и валютами транзакционны и пишутся в аудит-лог.
- Interest management, зоны и инстансы как отдельные процессы, фиксированный тик, симуляция отделена от представления.
- Ввод только через Input Actions. Строки UI только через ключи локализации.

## Памятка: «глупости», которые здесь уже находили (не повторять)

Серверный код, который выполняется каждый тик для каждого игрока:
- **Не перебирать всех** (игроков, письма, лоты) ради одного ответа. Поиск по имени — `ServerContext.FindPlayerByName` (индекс), а не цикл по `Players`; счётчик — кэш, пересчитываемый только при изменении версии данных (`MailSystem.Fill`).
- **Не создавать строки и объекты на каждом обращении.** Свойство, которое читают часто, кэширует результат (`ItemInstance.SourceId`); никаких `ToLowerInvariant()` / `ToString()` в цикле — сравнивать через `StringComparison.OrdinalIgnoreCase`.
- **Не строить то, что не уйдёт.** Снимки мира и состояния собираются только на тиках отправки (`PlayerOutbox.WorldEveryTicks` / `StateEveryTicks`).
- **Не слать то, что не изменилось.** Мир — по сущностям (`ProtocolCodec.EncodeWorld` + `NetworkClientSession.Complete`), приватное состояние — только при изменении (`ServerNetworkHost`). Редко меняющиеся данные (раскладки, настройки) — отдельным сообщением при изменении (`PanelsMessage`, `AccountSettingsMessage`), а не полем снимка.
- До и после правок производительности — замер: `cd tools/LoadTest && dotnet run -c Release -- local 100 15` (ориентир после ревизии v31: тик ≈ 1 мс, ≈ 56 КиБ/с на игрока при постоянно дерущихся ботах).

Чистота кода:
- **Один помощник — одно место.** Перед тем как писать приватный `NameOf` / поиск в сумке / `Notify`, найти готовый: `ServerContext.NameOf`, `Inventory.IndexOfInstance`, `InventorySystem.FindInBag`.
- **`bool`-результат значит «получилось».** Не `!= ОдинВидОшибки` (так было в `WalletSystem.Credit`: ошибка считалась успехом).
- **Ошибка одной команды не роняет тик**: обработка команд в `GameServer.Tick` изолирована; в тестах `RethrowCommandErrors = true`, чтобы ошибки не прятались.
- Не оставлять мёртвое: дубли после переноса логики, пустые заготовки, устаревшие комментарии «до модуля N».
- Сменился формат сети — поднять `NetworkConstants.ProtocolVersion` и версию в `docs/PLAY_WITH_FRIEND.md`.

Unity (в тестах вне Unity не видно):
- Unity 6.3 имеет свой `UnityEngine.EntityId`: в файле с `using UnityEngine;` и нашим `EntityId` обязателен псевдоним `using EntityId = Game.Shared.Core.EntityId;`.
- NUnit в Unity — версия 3.5: для коллекций не `Does.Not.Contain(x)`, а `Has.No.Member(x)`.
- Mono может считать `float` с повышенной точностью: перед округлением — явное `(float)` (`CombatMath.RoundAmount`).
- `JsonUtility` не хранит `null`: строки приходят `""`, объекты — пустыми; при загрузке нормализовать (`ItemRecords.NullIfEmpty`), в тестах это имитирует `JsonUtilityLike`.
- В сборке у `CreatePrimitive` нет материала URP — только `WorldPrimitives.Create`. Значения `QualitySettings`, изменённые в Play mode, остаются в проекте — возвращать при выходе.
- Не использовать API с `int instanceId` (уходят в 6.3+): работать через GUID / путь ассета.
- Части фигур и окружения — только `WorldPrimitives.Part` (без коллайдера) с общим материалом `Colored` / `Glow`; не `renderer.material.color` (создаёт материал на каждый объект и не освобождает его). Коллайдер — один на сущность, на корне (`EntityView`), иначе клик не найдёт сущность.
- Туман и свечение (`_EMISSION`) из кода не включать: в сборке их варианты шейдера вырезаются, в редакторе работает — в игре нет. Для «светящихся» частей — материал Unlit (`WorldPrimitives.Glow`).
- Новая картинка или фигура: значок — `Resources/Icons/<группа>/<Icon>.png` (+ `.meta`), фигура — ключ `VisualShape` в `WorldFigures.Recipes`; без картинки показывается название, без фигуры — капсула.
- Новый файл в `My project/Assets` — сразу с `.meta` (формат как у соседних: `fileFormatVersion: 2` + `guid:` из 32 случайных hex-символов, без повторов). Иначе Unity создаст его у разработчика, и тот должен будет коммитить. Проверка: `git ls-files Assets | grep -v '\.meta$'` — у каждого файла и папки есть `.meta`.

Проверки:
- **Проверка, которая не может упасть, бесполезна.** Новую проверку испытать пробной ошибкой. Компилировать так, как это делает Unity: каждая сборка `.asmdef` отдельно, без транзитивных ссылок, с типами Unity 6.3 и NUnit 3.5; режимы «редактор» и «сборка игры», с пакетом Localization и без.
- Новый тест на исправление должен падать без исправления — проверить это, временно откатив правку.
