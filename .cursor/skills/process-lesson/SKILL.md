# Process Lesson

## Когда использовать

- `references/transcripts/*.vtt`, `references/slides/`
- «Разбери урок / vtt / транскрипт» / «вынеси правила»
- «Запиши правила» → фаза записи (только явно)

Следовать `.cursor/rules/transcript-analysis.mdc`.

## Senior-review (обязательно)

На каждый вывод — призма **Unity-сеньора (~8 лет)**:
- production, масштаб команды, perf, debug, версии API;
- где совет курса **узок**, **устареет** или **дорог** в поддержке;
- подвохи в колонке **⚠️ Подвохи / слабости**; при серьёзных рисках — понизить tier.

## Фаза анализа (по умолчанию)

1. Один VTT (± slides из папки с таким же номером) на блок ответа.
2. Таблица: `# | Вывод | Tier | → rule file | Таймкод | Обоснование tier | ⚠️ Подвохи / слабости`.
3. Секции: **Не выносить**, **⚠️ Противоречия**, **Вопросы пользователю**.
4. Стоп. Без `.mdc`, lesson doc, кода.

## Фаза записи (только явная просьба)

«запиши правила», «добавь в mdc», «обнови rules».

1. Конфликты с existing rules — не писать без решения.
2. В `.mdc` — только одобренные выводы; tier; русский текст; API латиницей.
3. Оговорки из «подвохов» — кратко в bullet или в `architecture.md` deprecated.

## Анти-паттерны

- Вывод без колонки подвохов
- 🔴 из demo или без senior-проверки
- Запись без «запиши»
- VTT при обычном кодинге (rules уже есть)
